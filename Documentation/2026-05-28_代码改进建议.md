# 代码改进建议

基于对项目代码的全面评审，按优先级排列以下改进建议。

---

## P0 — 功能缺陷（当前影响正确性）

### 1. 防御系统未接入伤害计算

**问题：** `BattleFieldState.TryApplyDamage()` 直接减去伤害值，未使用 `CardRuntime.Defense`：

```csharp
// BattleFieldState.cs:473-480
public static bool TryApplyDamage(string targetCardId, int damage, out int appliedDamage)
{
    // ...
    damage = Mathf.Max(0, damage);
    appliedDamage = Mathf.Min(damage, rt.Hp);
    rt.Hp -= appliedDamage;  // 未扣除防御
    return true;
}
```

但 `DefenseBuffHandler` 已正确读写 `rt.Defense`，且 `BattleBuffState` 能正常挂载/到期移除 Buff。**防御字段完整存在，但不生效。**

**修复方案：** `TryApplyDamage` 中计算减伤 `damage = Mathf.Max(0, damage - rt.Defense);`

---

## P1 — 架构问题（重构收益高）

### 2. 全局静态类导致不可测试

**问题：** 核心逻辑类均为 `static`，包括 `BattleFieldState`、`BattleTurnSystem`、`BattleEventBus`、`SkillSystem`、`SkillValidator`、`SkillPipeline`、`SkillDefinitionRegistry`、`BattleBuffHandlerRegistry`。无法 Mock、无法隔离、无法写单元测试。

**影响：**
- 无法验证 `SkillSystem.TryCast` 中 event 发布顺序是否正确
- 无法测试 `BattleFieldState.TrySwitchActive` 的边界条件
- 修改后靠场景启动手动测试，回归成本高

**改进方向：** 将 `BattleFieldState`、`BattleTurnSystem`、`BattleEventBus` 改为实例类，注入到 `BattleContext` 中。`BattleFacade` 从 `BattleContext.Current` 获取这些实例。

### 3. 两个回合计数器不同步

**问题：** `BattleContext.CurrentTurn` 有 `SetCurrentTurn(int turn)` 但无处调用；实际回合计数由 `BattleTurnSystem._roundNumber` 独立维护。两套并存的回合号必然产生混淆。

| 位置 | 字段 | 是否实际使用 |
|------|------|-------------|
| `BattleContext` | `CurrentTurn` | 否（从未被 Set） |
| `BattleTurnSystem` | `RoundNumber` | 是 |

**改进方向：** 删除 `BattleContext.CurrentTurn`，所有回合查询统一走 `BattleTurnSystem.RoundNumber`。

---

## P2 — 代码质量（整洁度与健壮性）

### 4. 技能 Pipeline 缺少回滚机制

**问题：** `SkillPipeline.Execute` 顺序执行所有 Effect，遇失败不中断、不回滚：

```csharp
for (var i = 0; i < effects.Count; i++)
{
    var effect = effects[i];
    if (effect != null) effect.Execute(context);  // 某 Effect 失败后继续执行后续
}
```

**场景：** 一个技能链中有 Damage（扣血）→ SelfHpDrain（自伤），如果 Damage 成功但 SelfHpDrain 导致施法者死亡，或 SelfHpDrain 因校验失败跳过但 Damage 已执行——此时技能次数已消耗但效果不完整。

**改进方向：** `ISkillEffect.Execute` 返回 `bool` 表示成功/失败；`SkillPipeline` 遇失败时可选择回滚已生效 Effect（或在 Effect 层面保证其幂等/可安全重入）。

### 5. 字符串重复 Trim

**问题：** 几乎所有方法都重复调用 `.Trim()`：

| 文件 | 出现次数 |
|------|---------|
| `BattleFieldState.cs` | ~30 处 |
| `BattleTurnSystem.cs` | ~10 处 |
| `BattleFacade.cs` | ~5 处 |

正常化应在数据进入边界时完成（`BattleStartContext.SetSelectedDeck` / `BattleFieldState.EnsureInitialized`），内部假定已规范化。

### 6. 空值检查模式不一致

**问题：** 多处出现 `dest?.Clear(); if (dest == null) return;` 的模式。`?.` 在 null 时跳过调用，但紧接着又手动 null 检查，增加了认知负担但不增加安全性。统一为：

```csharp
if (dest == null) return;
dest.Clear();
```

或者接受 `?.Clear()` 是唯一防御手段且不补 null 检查。

### 7. 异常捕获过于宽泛

**问题：** FleetStore 使用 `catch (Exception ex)` 吞掉所有异常：

```csharp
try { ... }
catch (Exception ex)
{
    Debug.LogWarning($"Load fleet data failed: {ex.Message}");
    _cached = CreateDefaultFromCollection();
    return _cached;
}
```

开发阶段应让异常崩溃以暴露问题；`catch` 应仅限于预期的 `IOException` / ` CryptographicException`。

## P3 — 功能待完成

### 8. 敌方 AI 未实现

**问题：** `AutoPassRemainingEnemyActions()` 跳过全部敌方行动：

```csharp
public static void AutoPassRemainingEnemyActions()
{
    // 不是真实 AI，只是遍历登记"已行动"
    for (var i = 0; i < EnemyCardIdsBuffer.Count; i++)
    {
        if (!EnemyActedCardIds.Contains(id))
            TryCompleteCardAction(id);
    }
}
```

另外代码中还有注释 `// TODO(PvP): 抛硬币决定先手` 表明 PvP 先手逻辑也未实现。
