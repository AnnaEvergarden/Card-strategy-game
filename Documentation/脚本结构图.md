# 脚本结构图

> 本文档随 `Assets/Scripts/` 下脚本的增改而更新，用于快速查看分层与各脚本/文件夹职责。
> 最后更新：2026-10-05（对齐六层架构迁移后的当前代码结构）

## 分层概览

```
Presentation（表现层）    BootstrapScene/GameBootstrap 启动入口；各场景 Controller/Panel/View
        ↓ 只调用 Application 公开接口
Application（应用层）     Account / CardCollection / Fleet / Inventory 用例服务 + Events + BattleEntry/Loading/Login
        ↓ 只调用 Domain 公开接口
Domain（领域层）          Account / Build / Card / CardCollection / Fleet / Inventory / Level / Skill /
                         Battle(仅 BattleStartContext) / Currency / Events / Common / Config —— 纯业务，不依赖 Unity
        ↓ 通过仓储接口持久化
Repository（仓储接口在 Domain，实现在 Infrastructure/Repository）
        ↓
Infrastructure（基础设施层） DI / Resource / Config / Save / Scene / UI / Event / Audio /
                         Transaction / Persistence(Mapper+SaveData) / Repository 实现
        ↓
Unity（团结引擎）
```

- **依赖注入**：`GameBootstrap` 启动时创建 `ServiceContainer`，按序注册 IResourceService、IConfigService、ISceneService、IUIService、ISaveService、IAudioService 等服务；`[Inject]` 标记自动注入。
- **启动流程**：GameBootstrap（Awake 单例 + DontDestroyOnLoad）→ 创建服务 → LoadingController 显示进度 → 热更新检查（HotUpdateService，最多重试 3 次）→ 加载入口场景。
- **资源与配置**：业务层只通过 `ResourceId`（Domain/Common）向 `IResourceService` 请求资源；配置 JSON 优先、SO 备选（ConfigService）。
- **当前缺口**：战斗系统核心（回合/技能管线/Unit/AI）尚未在新结构下重建，详见文末「已知缺口与待办」。
